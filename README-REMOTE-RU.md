# AyuGram Remote — экспериментальные исходники

Это изменённый полный репозиторий AyuGram Desktop на основе коммита
`0f2a31bb420de98f331990432265b131b8d836b5`. Все рекурсивные Git-подмодули включены.
Оригинальные лицензии и авторство сохранены. TDLib не используется.

**Это ещё не готовый клиент для повседневного использования.** Код интеграции написан,
но C++-цели не были скомпилированы и запущены. Настоящий вход в Telegram, установка
Docker на VPS и работа оригинального интерфейса через новый транспорт не проверены.
Серверные проверки используют тестовый MTProto-адаптер, а не Telegram.

## Что изменено

| Часть | Реализация в исходниках |
| --- | --- |
| Движок VPS | Новая цель `AyuGramRemoteEngine`: оригинальные `MTP::Instance`, сессии, шифрование и соединения, запускаемые через `QCoreApplication`. Нет `QApplication`, Xvfb или скрытого окна. |
| Ключи Telegram | Только файл `state/keys` на VPS. Клиентский транспорт не создаёт MTProto-сессии; использование старого профиля с ключами запрещено. |
| Транспорт | TL-запросы и ответы через JSONL, OpenSSH и Unix-сокет. Проверяются токен, идентификатор сервера и отпечаток TL-схемы. |
| Интерфейс | Исходный интерфейс AyuGram с подменой транспорта в `MTP::Instance`. Мастер подключения пока отдельное окно PySide6. |
| Хранилище VPS | SQLite WAL: события, версии сообщений, удаления, результаты запросов. Полученные фрагменты медиа сохраняются в файлы. |
| Медиа-кэш | 3 GiB по умолчанию, LRU-очистка. Лимит меняется в мастере без остановки сервера. |
| История AyuGram | Импорт сохранённых текстовых версий и удалений в оригинальную базу AyuGram, с отдельным курсором повторной доставки. |
| Фоновая работа | Получение push-обновлений и периодический `updates.getDifference` на VPS, независимо от GUI. Docker настроен на перезапуск. |
| Локальный кэш | Исходный кэш AyuGram, сохранение ответов разрешённых запросов и архив событий на диске. Для запуска без SSH есть офлайн-флажок. |
| Ghost Mode | Исходные клиентские настройки плюс серверная блокировка online, typing, read receipts и просмотров историй по умолчанию. |
| Установка | SSH-мастер передаёт исходники, устанавливает Docker, собирает и запускает контейнер, получает токен сопряжения; затем открывается изменённый AyuGram. |

## Что осталось незавершённым

- **Полный офлайн-режим.** Кэш возвращает ответы на ранее выполненные идентичные
  запросы. Нет полной локальной модели чатов, поиска и произвольной пагинации без
  сервера. Наличие отдельных файлов кэша не гарантирует, что весь ранее просмотренный
  диалог восстановится после перезапуска.
- **Восстановление всех пропусков.** Общий `updates.getDifference` реализован;
  отдельный цикл `updates.getChannelDifference` для каждого канала/супергруппы и
  пересоздание снимка после `differenceTooLong` пока отсутствуют. Большой разрыв
  помечается `sync_gap` в базе; архив нельзя считать полным.
- **Автономная загрузка медиа.** VPS кэширует фрагменты, запрошенные интерфейсом.
  Фоновый обход всех чатов и загрузка новых вложений без запущенного GUI не реализованы.
  Файлы вложений удалённых сообщений пока не восстанавливаются в GUI через архивный мост.
- **Полный перенос логики AyuGram.** Сервер ведёт собственный архив на основе
  MTProto-обновлений; оригинальные UI-зависимые службы AyuGram целиком не перенесены.
  История текстовых сообщений подключена к исходной клиентской базе, но её отображение
  ещё требует проверки на собранном клиенте.
- **Паритет всех функций.** Звонки, веб-приложения, внешние переводчики и другие
  прямые сетевые функции GUI не перенесены на VPS. В сетевой изоляции они не работают.
  Обёртки `invoke*`, экспорт авторизации и вход по QR отключены.
- **Жизненный цикл аккаунта.** Один серверный каталог обслуживает один Telegram-аккаунт.
  После первого входа привязка запрещает новый вход, чтобы не смешать архивы. Выход
  из аккаунта может отозвать серверную сессию. Повторный вход и смена аккаунта пока
  требуют отдельного состояния сервера и нового клиентского профиля.
- **Серверные настройки Ghost Mode.** По умолчанию сервер принудительно блокирует
  присутствие и прочтения даже при выключенном клиентском переключателе. Параметр
  сервера `--allow-presence` отключает эту дополнительную блокировку, оставляя
  оригинальную клиентскую фильтрацию. Синхронизация отдельных переключателей с VPS
  пока не сделана.
- **Проверка нативной части.** Не подтверждены компиляция/линковка C++, работа
  мастер-окна PySide6, вход с кодом и облачным паролем, восстановление после реального
  перезапуска VPS. В поставке нет исполняемых файлов и готового Docker-образа.

## Подготовка клиента на Arch Linux

Нужны Python 3.9+, PySide6, OpenSSH и Bubblewrap. Для сборки — зависимости оригинального
AyuGram из [docs/building-linux.md](docs/building-linux.md) или его Docker-среда.
Для этой версии используйте Debug. Нужны одинаковые `api_id` и `api_hash` при сборке
клиента и заполнении мастера сервера.

После распаковки работайте в папке `AyuGramDesktop`. Подмодули уже находятся внутри;
повторное клонирование не требуется. Пример сборки с предоставляемой upstream средой:

```bash
docker run --rm -it \
  -u "$(id -u)" \
  -v "$PWD:/usr/src/tdesktop" \
  -w /usr/src/tdesktop \
  ghcr.io/telegramdesktop/tdesktop/centos_env:latest \
  bash -lc 'cd Telegram && ./configure.sh \
    -D CMAKE_BUILD_TYPE=Debug \
    -D TDESKTOP_API_ID=YOUR_API_ID \
    -D TDESKTOP_API_HASH=YOUR_API_HASH \
    -D AYUGRAM_REMOTE_ONLY=ON \
    -D DESKTOP_APP_DISABLE_AUTOUPDATE=ON \
    -D DESKTOP_APP_DISABLE_CRASH_REPORTS=ON \
    && cmake --build ../out --config Debug --target Telegram --parallel 2'
```

Замените `YOUR_API_ID` и `YOUR_API_HASH` своими значениями до запуска. Это команда
для проверки и сборки исходников, а не подтверждённый успешный рецепт этой новой цели.
Образ по умолчанию использует плавающий тег `latest`; для воспроизводимой сборки
после проверки зафиксируйте его digest. Обычно бинарник Linux находится в
`out/bin/AyuGram`; при multi-config-генераторе путь может отличаться.

Если PySide6 не установлен системно, установите его в отдельное окружение:

```bash
python3 -m venv remote/.venv
remote/.venv/bin/python -m pip install -r remote/requirements-gui.txt
export PATH="$PWD/remote/.venv/bin:$PATH"
python3 remote/setup.py
```

OpenSSH и Bubblewrap должны быть установлены средствами Arch. Экспорт `PATH` также
нужен диалогу SSH askpass, использующему `#!/usr/bin/env python3`.

## Первое подключение

1. Запустите `python3 remote/setup.py`.
2. Выберите «Установить на новый VPS», укажите адрес, SSH-порт, ключ при необходимости,
   **новую** папку профиля и путь к **собранному из этого репозитория** AyuGram.
3. Укажите те же `api_id`/`api_hash`, что использованы при сборке клиента, и лимит кэша.
4. Подтвердите установку. OpenSSH отдельно запросит пароль/пароль ключа и проверку
   отпечатка сервера. Пароль SSH не записывается в профиль.
5. После завершения сборки контейнера откроется исходный интерфейс входа в Telegram:
   номер, код, облачный пароль при необходимости. Эти запросы идут через VPS.

Автоматический установщик рассчитан на root-доступ по SSH к Debian/Ubuntu с systemd,
работающими пакетными репозиториями и Python 3 на хосте. Старые EOL-выпуски отдельно
не проверены. Сборка C++ на слабом VPS может не поместиться в память; минимальные RAM,
диск и время сборки для этой цели пока не измерены. Существующий Docker не заменяется.

Установщик создаёт `/opt/ayugram-remote/source`, `install.json`, `state` и контейнер
`ayugram-remote`. При наличии сессии или контейнера повторная установка отказывается
их заменять. Для уже установленного сервера используйте «Подключить установленный
сервер» с новой локальной папкой либо «Запустить сохранённый профиль».

Чтобы изменить квоту, выберите «Изменить лимит кэша сервера», укажите существующий
профиль и новое значение. Уменьшение квоты удаляет старые файлы кэша; архив текста
остаётся. Значение 0 выключает хранение новых фрагментов и очищает этот кэш.

## Запуск сохранённого профиля без мастера

```bash
PYTHONPATH=remote python3 -m ayuremote.launcher \
  --profile "$HOME/.local/share/ayugram-remote/default" \
  --binary "$PWD/out/bin/AyuGram"
```

Для запуска без соединения с VPS добавьте `--offline`. Он использует только
имеющийся кэш с ограничениями, описанными выше. Для CLI OpenSSH использует обычный
терминальный ввод. Закрытие GUI не останавливает контейнер на сервере.

Запускать бинарник напрямую нельзя: по умолчанию `AYUGRAM_REMOTE_ONLY=ON` требует
профиль удалённого транспорта. Launcher дополнительно запускает GUI через
`bwrap --unshare-net`. При недоступном Bubblewrap он завершается, не переходя
к прямому соединению с Telegram. SSH остаётся снаружи сетевого пространства и
передаёт данные через Unix-сокет.

## Где находятся данные

| Путь | Содержимое |
| --- | --- |
| VPS: `state/keys` | Ключи оригинального MTProto и конфигурация DC; права 0600. |
| VPS: `state/token` | Токен доступа к серверному API; права 0600. |
| VPS: `state/archive.sqlite3` | Сообщения, версии, отметки удаления, журнал и курсор синхронизации. |
| VPS: `state/media/` | Полученные TL-ответы с фрагментами файлов, ограниченные квотой. |
| ПК: `profile.json` | SSH-адрес, путь к ключу, серверный токен, идентификатор профиля и сервера. |
| ПК: `tdata/` | Локальные настройки, данные пользователя и исходный кэш AyuGram; без Telegram auth keys. |
| ПК: `cache/` | Ответы чтения, события, архивные записи и курсоры нового транспорта. |

Лимит 3 GiB относится к **файловому медиа-кэшу**, а не к общему размеру SQLite,
журнала, Docker-образов или локального профиля. Текстовый архив и журнал растут
постоянно. Кэш хранит полученные фрагменты, а не обязательно цельные экспортируемые
файлы. Автоматическое ограничение всего диска здесь не реализовано.

Токен в локальном профиле даёт доступ к аккаунту через VPS: отсутствие Telegram-ключей
на ПК не делает профиль несекретным. На сервере ключи и база не зашифрованы отдельным
паролем приложения; защита обеспечивается правами файлов и SSH при передаче.
Сервер слушает только `127.0.0.1:17555`; открывать этот порт наружу не требуется.
Не смешивайте новый профиль с существующим `tdata` обычного AyuGram.

## Проверки и дальнейшая работа

Результаты выполненных проверок: [remote/VALIDATION.md](remote/VALIDATION.md).
Описание протокола: [remote/PROTOCOL.md](remote/PROTOCOL.md).
Список подмодулей: [remote/UPSTREAM-SUBMODULES.txt](remote/UPSTREAM-SUBMODULES.txt).

```bash
python3 -m unittest discover -s remote/tests -v
python3 remote/check_source.py
python3 -m compileall -q remote
bash -n remote/install-server.sh
git diff --check
```

Следующий обязательный этап — собрать обе C++-цели, исправить ошибки сборки, затем
проверить на отдельном тестовом аккаунте весь путь «SSH → Docker → код → 2FA → сообщения
→ перезапуск → архив». После этого нужны каналовые difference-циклы, автономная
загрузка вложений и полноценная локальная модель данных для офлайн-режима.
